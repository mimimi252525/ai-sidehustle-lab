# AI副業ラボ

初心者向けの日本語AIツール比較・副業ガイドです。Astro + TypeScript で静的HTMLを生成します。プロンプト生成はブラウザ内で完結し、外部APIやAPIキーは不要です。

## ローカル開発

Node.js 22.12 以上を使用してください。nvm を使う場合は `nvm use` で Node.js 22 を選べます。

```sh
npm install
npm run dev
```

ターミナルに表示されるローカルURLを開きます。

```sh
npm run check
npm run build
npm run preview
```

ビルド出力は `dist/` です。CIや公開時はロックファイルに基づく `npm ci` で再現できます。

## 公開

GitHubリポジトリを接続し、以下の設定を使用します。

| 設定 | Cloudflare Pages | Vercel |
| --- | --- | --- |
| プロジェクトルート | リポジトリルート | リポジトリルート |
| フレームワーク | Astro | Astro |
| Node.js | 22 | 22.x |
| ビルドコマンド | `npm run build` | `npm run build` |
| 出力先 | `dist` | `dist` |

1. Cloudflare Pages では Git に接続してプロジェクトを作成します。Vercel では同リポジトリをインポートします。
2. 本番の環境変数 `SITE_URL` に公開URLのHTTPSオリジンを指定します。独自ドメインを使う場合はそのURLを指定します。
3. ビルドして公開します。初回に公開URLが確定する場合は、環境変数を設定して再ビルドします。
4. 公開先でトップページ、`/robots.txt` と `/sitemap-index.xml` を確認します。

ローカルで公開用ビルドを再現する場合は `.env.example` を `.env` にコピーし、`SITE_URL` を設定します。URL未設定時は canonical・サイトマップを出力せず、検索エンジンへの登録を抑止します。プレビュー環境では `SITE_URL` を空にする場合、共有の `.env` にも設定しないでください。

## コンテンツの更新

- AIツールは `src/data/tools.json`、ガイドは `src/data/guides.json` を編集します。`id` はURLに使用するため、公開済みの値は維持してください。記事を修正した場合は `updated`（YYYY-MM-DD）も更新します。
- 料金・無料枠・商用条件は利用する地域とプランの公式情報を参照し、確認できない場合は「要確認」とします。
- 下書きはPRでレビューし、公式情報・権利・リンクを確認してからマージします。販売・広告の導入時は、掲載箇所にPR表記を付け、提携リンクに `rel="sponsored noopener noreferrer"` を設定します。
- 運営者情報とポリシーは `src/data/site.ts` にあります。問い合わせの初期窓口は公開の GitHub Issues です。非公開の問い合わせ先を用意した際は `src/pages/[info].astro` と案内を更新してください。

## 記事制作の半自動化

GitHub Actions は月・水・金の日本時間9時（UTC 0時）を目安に `main` から動きます。混雑時は遅延する場合があります。実行ごとに優先度が最も高い未処理の候補を最大1件選び、`editorial/drafts/<id>.md` に保存します。`OPENAI_API_KEY` を設定すると、SEOタイトル・説明文、導入、見出しと本文、まとめを含む日本語原稿を作成します。キーが未設定の場合は従来どおり構成案と執筆指示を作成します。どちらも人が内容と事実関係を確認し、公開用PRは別途作成します。

### OpenAI API の設定と費用

- GitHub リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で、OpenAI API のキーを `OPENAI_API_KEY` として登録してください。ローカルで試す場合は、シェルに同名の環境変数を設定します。キーはリポジトリやPRに記載しないでください。
- キーがある場合、候補1件につき OpenAI Responses API へ最大1回リクエストします。送信内容は候補のテーマ・カテゴリ・読者・検索意図・キーワード・見出し案です。APIがエラーを返した場合は処理を停止し、候補を未処理のまま残します。ログにはHTTPステータスなどの概要を出力します。
- APIは入力・出力トークンに応じて課金されます。無料クレジットの有無はアカウントでご確認ください。ChatGPT の契約と API の利用料金は別です。キー未設定で構成案を生成する場合や、未処理候補がない場合はAPI課金がありません。GitHub Actions の実行時間はリポジトリのプランに応じて消費します。
- 概算の例として、`gpt-4.1-mini` の入力が100万トークンあたり0.40米ドル、出力が1.60米ドルの場合、入力約1,000・出力1,500〜3,500トークンで **1記事あたり約0.0028〜0.0060米ドル** です。出力上限は3,500トークンです。実際の金額はトークン数と適用単価によって変わるため、設定前に [OpenAI API 料金表](https://openai.com/api/pricing/) を確認してください。

### 初回に設定すること

1. このワークフローを導入するPRをレビューして `main` に統合します。定期実行と手動実行には、ワークフローがデフォルトブランチの `main` にある必要があります。
2. GitHub の **Settings → Actions → General** で GitHub Actions を有効にします。**Workflow permissions** の **Allow GitHub Actions to create and approve pull requests** を有効にすると、ワークフローがドラフトPRを作成できます。用途ごとのトークン権限はワークフローで指定します。組織ポリシーで設定を有効にできない場合は手動でPRを作成します。
3. GitHub の **Settings → Rules → Rulesets** などで `main` にPR経由の統合と必要なレビューを要求します。自動処理用の `article-draft/*` ブランチは Actions のトークンで新規作成できるようにします。
4. Vercel のプロジェクト設定で本番ブランチを `main` に設定し、本番用の `SITE_URL` を設定します。編集中の記事も社外非公開にしたい場合は、公開PRのプレビューデプロイを保護または無効化します。GitHub リポジトリが公開の場合、下書きのMarkdown自体はGitHub上で閲覧できるため、機密情報は置かないでください。

### 手動実行と下書きの確認

1. GitHub の **Actions → 記事の編集用下書きを準備 → Run workflow** を開き、`main` を選んで実行します。ローカルで試す場合は作業ブランチで `npm run draft:article` を実行します。
2. 実行ログと `article-draft/<id>` ブランチのドラフトPRを開き、Markdownを確認します。PR作成が失敗してブランチがプッシュ済みの場合は、ログに表示される手動作成URLを開き、`main` をベースにPRを作ります。
3. 下書きを保管する場合は、ドラフトPRをレビュー可能に切り替え、確認・統合します。この統合で記事ページは増えません。採用しない候補を再生成したくない場合は、候補の状態を `retired` にする変更をPRで統合してください。
4. 候補は `data/article-ideas.json` で管理します。優先度は数値が大きい順です。`pending` が未処理、`drafted` が下書き済み、`published` が公開承認済み、`retired` が対象外です。既存の下書きファイル、公開用ガイドのID、リモートの専用ブランチに一致する候補も除外します。未統合の専用ブランチを削除すると、`main` で `pending` の候補は再び対象になります。候補を追加する前に既存記事と検索意図が重ならないことを確認します。

### 本文を編集して公開する

1. 下書きPRが統合された後、最新の `main` から記事公開用の作業ブランチを作ります。Codexなどを使う場合は、下書きと [記事公開前チェックリスト](editorial/publish-checklist.md) を渡し、一次情報を確認できるまで料金・無料枠・商用利用・提携条件を「要確認」とするよう指示します。AI生成の原稿も「要確認」項目と本文を公式情報で検証し、編集者が内容を修正・確定します。末尾の事実確認チェックリストとAIからの引き継ぎは編集用のため、公開本文には移しません。
2. 完成原稿を `src/data/guides.json` の既存形式に変換し、候補と同じ `id` を使います。`title`、`category`、`theme`（例 `lavender`）、`symbol`、`updated`、`description`、`sections`（各項目は `heading` と `body`）を指定します。広告・提携がある場合はタイトル直下に読者から見える「PR」または「広告」の表示を用意します。現行の本文はプレーンテキストで表示されるため、アフィリエイトリンクを導入する場合は適切な表示とリンク属性を記事テンプレートに実装します。
3. 公開前チェックを完了してから、同じIDの候補を `published` に変更します。管理対象の記事は、公開用ガイドデータに原稿があり、候補の状態が `published` の場合に限り、トップ・ガイド一覧・詳細ページに反映されます。
4. `npm run check` と `npm run build` を実行し、ガイド一覧、記事ページ、更新日、広告表記を確認します。公開用PRを作り、本文と確認済みの情報をレビューしてもらいます。
5. 承認後に公開用PRを `main` に統合します。Vercel の **Deployments** で本番ビルドが成功したことを確かめ、公開URLのガイド一覧と記事ページを確認します。
